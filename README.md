# Allergy & Health Tracker

تطبيق Android عربي لتسجيل الأدوية والحساسيات الدوائية والغذائية، مع حفظ البيانات محليًا، إدارة السجلات، إنشاء بطاقة طوارئ، وتصدير البيانات إلى PDF أو Excel/CSV.

## ما يعمل في النسخة الحالية — v0.9.1

- شاشة سجلات منظمة بزر إضافة واحد، مع اختيار نوع السجل داخل النموذج وتقارير قابلة للطي.
- نوع جديد «حساسية أخرى» وحقول جرعة/تكرار للأدوية.

- واجهة عربية من اليمين إلى اليسار مع أزرار وخطوط أكبر وتحسينات للوصول.
- دعم عدة مرضى/أفراد عائلة، مع اختيار المريض الحالي وتعديل/حذف ملفه.
- إضافة دواء / علاج عادي مع الاسم والمادة الفعالة والاستخدام أو الملاحظات.
- إضافة حساسية دوائية مع الأعراض وشدة التفاعل.
- إضافة حساسية غذائية.
- إضافة دواء تم تحمّله دون حساسية.
- إضافة مرض مزمن، عملية سابقة، أو ملاحظة طبية.
- حفظ بيانات المرضى مشفرة داخل AsyncStorage، مع حفظ مفتاح التشفير في Android SecureStore.
- شاشة سجلات كاملة مع التصفية حسب النوع.
- **عرض تفاصيل أي سجل**.
- **تعديل أي سجل محفوظ**.
- **حذف أي سجل بعد رسالة تأكيد**.
- **إضافة سجل جديد مباشرة من شاشة السجلات**.
- **تصدير سجلات المريض الحالي إلى PDF عربي قابل للمشاركة**.
- **تصدير سجلات المريض الحالي إلى CSV متوافق مع Excel**.
- بطاقة طوارئ تلخص الحساسية، الأدوية المسجلة، والأدوية المتحملة.
- تعديل بيانات الشخص ومشاركة بطاقة الطوارئ عبر قائمة المشاركة في Android.
- إنشاء نسخة احتياطية `.agbackup` مشفرة بكلمة مرور، تشمل جميع ملفات المرضى والسجلات والمرفقات الطبية.
- مشاركة النسخة المشفرة مباشرة عبر Google Drive أو WhatsApp أو أي تطبيق مشاركة على الجهاز.
- استعادة الملف من أي مكان مع تأكيد صريح قبل استبدال البيانات الحالية.
- فحص تحديثات GitHub من داخل التطبيق.
- GitHub Actions يبني APK مباشرة باستخدام Expo Prebuild + Gradle بدون الحاجة إلى EAS أو EXPO_TOKEN.

## تطوير السجل الصحي (قيد المراجعة في PR #8)

- إدارة تعديل وحذف الحالات والقياسات ونتائج المختبر، مع حفظ التاريخ المرتبط بالسجل.
- خط زمني موحّد يجمع السجلات القديمة والجديدة.
- عرض اتجاه القياسات ضمن النوع والوحدة نفسيهما فقط لتجنب مقارنة وحدات غير متوافقة.
- تقرير PDF شامل لملف المريض، ويذكر عدد المرفقات دون تضمين محتواها.
- بطاقة الطوارئ تشارك الأدوية والحالات النشطة المسجلة في نموذج الصحة الجديد.
- استيراد نصوص التحاليل ما زال في مرحلة التطوير: المحلل الحالي يعالج نصًا مستخرجًا مسبقًا، ولا يفتح PDF أو ينفذ OCR حتى الآن. لا تعتمد على هذه النسخة لاستيراد نتائج المختبر تلقائيًا.
- النسخ التلقائي إلى Google Drive الساعة 07:00 وOCR المحلي ما زالا غير متاحين حتى اكتمال دمج واختبار المكونات الأصلية والصلاحيات.

## إدارة السجلات

من تبويب **السجلات الصحية** يمكنك:

- الضغط على **إضافة سجل جديد** ثم اختيار نوع السجل من النموذج.
- استخدام الفلاتر لعرض كل السجلات أو نوع محدد.
- الضغط على **عرض** للاطلاع على جميع تفاصيل السجل.
- الضغط على **تعديل** لتعديل السجل وحفظ التغييرات.
- الضغط على **حذف** لحذف السجل بعد تأكيد العملية.
- الضغط على **تصدير PDF** لإنشاء ملف PDF يحتوي جميع السجلات وبيانات المستخدم ثم فتح قائمة المشاركة.
- الضغط على **تصدير Excel** لإنشاء ملف CSV بترميز UTF-8 قابل للفتح في Excel وGoogle Sheets.

## النسخ الاحتياطي والاستعادة

من تبويب **الإعدادات** افتح **النسخ والحماية**:

- **إنشاء ومشاركة نسخة احتياطية:** ملف `.agbackup` مشفر بكلمة مرور، يحتوي جميع المرضى والسجلات والمرفقات الطبية. احتفظ بكلمة المرور؛ لا يمكن استعادة النسخة دونها.
- **تصدير Excel:** ملف CSV بترميز UTF-8 مع BOM.
- **استعادة النسخة:** اختر ملف `.agbackup` وأدخل كلمة المرور نفسها، ثم راجع عدد المرضى والمرفقات وأكد الاستبدال. كما يقبل التطبيق النسخ القديمة غير المشفرة ويعرض تحذيرًا قبل استعادتها.

تُنشأ النسخة المشفرة محليًا ثم تُفتح قائمة مشاركة Android؛ لا يرفع التطبيق النسخة إلى خادم خاص به. على Android تُشفّر بيانات المرضى والنسخ التلقائية والمرفقات على الجهاز، ويُحفظ مفتاح الجهاز في SecureStore. النسخة الخارجية تستخدم تشفيرًا موثّقًا XSalsa20-Poly1305 مع اشتقاق مفتاح PBKDF2-SHA256 بعدد 210,000 دورة. احتفظ بكلمة مرور النسخة في مكان آمن. ملفات PDF وCSV التي تصدّرها يدويًا تبقى ملفات مشاركة عادية غير مشفرة، لذا تعامل معها كمعلومات خاصة. نسخة الويب تستخدم مخزن متصفح عاديًا لمفتاح التوافق ولا توفر حماية SecureStore الخاصة بأندرويد.

## بناء APK عبر GitHub Actions

الـ workflow باسم **Android preview APK** يقوم تلقائيًا بـ:

1. تثبيت الحزم.
2. تشغيل TypeScript check.
3. تشغيل Expo Prebuild لإنشاء مشروع Android.
4. إعداد Java 17.
5. بناء APK باستخدام Gradle.
6. رفع `allergy-guard-android.apk` كـ GitHub Artifact.
7. عند دفع tag يبدأ بـ `v` يتم أيضًا إنشاء GitHub Release وإرفاق APK.

مثال:

```bash
git tag v0.9.1
git push origin v0.9.0
```

## ملاحظات طبية

هذا التطبيق أداة تنظيم معلومات شخصية وليس أداة تشخيص أو وصف علاج. تسجيل دواء على أنه تم تحمّله لا يضمن سلامته مستقبلًا؛ يجب التأكد من الطبيب أو الصيدلي عند الحاجة.

## التحديث فوق النسخة القديمة

التطبيق يستخدم نفس `android.package` ويرفع `versionCode` في كل إصدار. حتى يقبل Android التحديث فوق نسخة مثبتة سابقًا، يجب أيضًا أن تكون النسختان موقعتين بنفس مفتاح التوقيع. احتفظ بطريقة التوقيع نفسها لكل الإصدارات المستقبلية.

## المزامنة السحابية مستقبلًا

النسخة الحالية محلية فقط. تمت إضافة واجهة `CloudSyncProvider` داخل `lib/sync/cloud-provider.ts` حتى يمكن لاحقًا إضافة Firebase أو Supabase أو مزود آخر بدون ربط شاشات التطبيق مباشرة بخدمة سحابية محددة.

## ملاحظات الحماية والقيود المعروفة في 0.9.1

- بيانات المرضى على Android تُخزن مشفرة، ومفتاح الجهاز محفوظ في Android SecureStore. تم تعطيل Android Auto Backup حتى لا تُستعاد البيانات المشفرة دون مفتاحها؛ استخدم النسخة اليدوية المشفرة عند الانتقال إلى جهاز آخر.
- المرفقات الجديدة تُشفّر على الجهاز وتُفك مؤقتًا عند فتحها. قد تبقى مرفقات أضيفت في إصدارات أقدم بصيغتها القديمة حتى يعاد إرفاقها أو ترحيلها.
- النسخ القديمة غير المشفرة ما زالت مقبولة للتوافق، ويظهر تحذير واضح قبل استعادتها.
- ملفات PDF وCSV المصدّرة ليست مشفرة؛ تعامل معها كمعلومات خاصة.
- نسخة الويب لا تستخدم Android SecureStore، لذلك لا تعتبر بيانات الويب محمية بالتشفير على مستوى الجهاز.
- نجاح فحص TypeScript والاختبارات وبناء APK/AAB لا يغني عن تجربة التطبيق على جهاز Android حقيقي.
